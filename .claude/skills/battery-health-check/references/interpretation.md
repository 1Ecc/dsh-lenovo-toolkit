# 电池数据判读规则

这份文件是「把一堆数字翻译成人话」的依据。目标读者是两类人同时在场：一线服务顾问要能照着说，
终端用户要能听懂并且信。所以每条结论都要能追溯到具体字段，不能凭感觉下判断。

## 一、两种健康度口径，先分清再下结论

`metrics.env` 里有两个健康度，含义完全不同，混用是最容易翻车的地方：

| 字段 | 含义 | 用途 |
|---|---|---|
| `health_pct_os` | 操作系统对外公布的最大容量百分比（macOS 系统设置里显示的数字 / Windows 报告口径） | **对客户说话用这个**，因为他自己点开系统设置能看到同样的数字 |
| `health_pct_raw` | 电量计实测：`满充容量 ÷ 设计容量` | **判断电芯物理状态用这个**，它直接来自电池管理芯片 |

**两者一致（差 < 3 个百分点）**：正常情况，直接按数值判级。

**两者不一致（差 ≥ 3 个百分点）**：必须在报告里主动解释，不解释客户会觉得你在糊弄。常见原因：

- **Apple Silicon 机型的平滑算法**。macOS 不直接暴露 `满充/设计`，而是叠加了循环数、
  高电量停留时长、温度历史等因素做长期平滑。系统口径明显低于电量计实测，在 M 系列上很常见。
- **电量计尚未完成校准**。刚开机没多久、或长期插电没有完整充放电时，`AppleRawMaxCapacity`
  可能还是上次校准值。看 `BatteryData.LifetimeData.CycleCountLastQmax` 与 `cycle_count` 的差：
  差得越多，说明离上次容量重新标定越久，实测值越不新鲜。
- **Windows 上 FCC 长期不更新**。部分机型要完整放电到 5% 以下再充满才会刷新 FullChargeCapacity。

判读时的取舍：**两个口径取较低者作为风险判断依据，取系统口径作为对客户陈述的数字。**
偏保守，但服务场景下宁可保守——把好电池说坏会被投诉，把坏电池说好会被返修。

如果 `health_pct_raw` > 100%（满充容量超过设计容量），这不是异常，新电池和刚校准过的电池
经常这样，设计容量本来就是留了余量的标称值。照常判为健康即可，不要拿来当卖点也不要当问题讲。

## 二、健康度分级

以「两个口径中较低者」判级：

| 区间 | 定级 | 含义 |
|---|---|---|
| ≥ 90% | **优秀** | 基本等同新机状态 |
| 80% ~ 90% | **良好** | 正常老化区间，续航有可感知下降但不影响使用 |
| 70% ~ 80% | **衰减明显** | 已跨过行业通行的 80% 更换线，续航缩水明显，可以谈更换了 |
| 60% ~ 70% | **建议更换** | 续航大幅缩水，脱离电源的可用时间已经不可靠 |
| < 60% | **强烈建议更换** | 除续航外，还可能出现掉电跳变、突然关机 |

80% 这条线的由来：厂商保修条款和行业惯例都以「满充容量降至设计容量的 80%」作为电池达到
预期寿命终点的判据，不是随便定的。跟客户解释时可以直接引用这个口径。

## 三、循环次数分级

用 `cycle_count / design_cycle_count` 的比值判断，不要只看绝对次数——不同机型的设计循环次数
差别很大（老机型可能只有 300 次，近几年的主流机型多为 1000 次）。

| 比值 | 定级 |
|---|---|
| < 25% | 使用很轻 |
| 25% ~ 50% | 正常 |
| 50% ~ 80% | 使用较多，进入寿命中后段 |
| ≥ 80% | 已接近设计寿命终点 |
| ≥ 100% | 已超设计寿命，即使健康度尚可也应主动提示 |

**Windows 侧的坑**：`design_cycle_count` 在 Windows 上取不到（powercfg 和 WMI 都不暴露），
采集脚本会留空。这时按 1000 次做参考基准，**并且必须在报告里写明这是假设值**，
不能让客户以为是从他机器上读出来的。

`cycle_count` 为 0 或空也很常见（部分厂商的电池固件不上报）。这时就别提循环次数，
只用容量和衰减速率说话，不要编一个数出来。

---

## 四、衰减速率：比绝对值更有信息量

「88% 健康度」本身说明不了问题——如果是 800 次循环后的 88%，那是好得离谱；
如果是 50 次循环后的 88%，那要查原因。所以速率是判读的重点。

```
实测速率 = (100 - 健康度) / 循环次数          单位：百分点/次
规格速率 = 20 / 设计循环次数                   单位：百分点/次
倍率     = 实测速率 / 规格速率
```

| 倍率 | 判读 |
|---|---|
| ≤ 1.2 | 符合或优于厂商规格 |
| 1.2 ~ 2 | 略快于规格，通常与使用习惯有关（高温、长期满电插电） |
| 2 ~ 3 | 明显偏快，建议排查使用环境 |
| > 3 | 异常，需要结合异常信号清单判断是否是个体故障 |

**循环次数很少时（< 50 次）这个公式不可靠**：分母太小，一两个百分点的测量误差就会把倍率
放大到吓人的程度。这种情况只说「循环次数尚少，衰减趋势需要积累更多数据才能判断」，
不要给倍率结论。趋势图会自动在这种情况下画成推算区间而不是单一确定线，报告的措辞要和图一致。

同理，**当两个口径分歧较大时，分别算两个倍率并给出区间**，不要只挑难看的那个说。

## 五、异常信号清单

以下任意一条命中，都要在报告里单列出来，并且优先级高于健康度分级：

| 字段 | 触发条件 | 含义与话术 |
|---|---|---|
| `permanent_failure_status` | 非 0 | 电池管理芯片记录了永久性故障标志。**这是硬故障，直接建议送修检测**，不要只谈更换电池。 |
| `cell_disconnect_count` | > 0 | 电芯曾出现断连。偶发 1~2 次可能是运输或极端温度导致；持续增长要送修。 |
| `condition` | 非 `Normal` / `Good` / `OK` | 系统已经判定电池需要维护或更换，直接引用系统结论。 |
| `lifetime_max_temp_c` | ≥ 50 | 历史最高温偏高。高温是锂电池衰减的第一杀手，重点讲散热和使用环境。 |
| `lifetime_max_temp_c` | ≥ 60 | 历史高温严重，衰减偏快基本可以归因到这里。 |
| `temperature_c` | ≥ 45（当前温度） | 当前就在高温下，提醒客户检查散热口积灰、是否在被褥/沙发上使用。 |
| `full_charge_capacity_mah` | 缺失或为 0 | 电量计未上报，多半是校准问题，建议完整充放电一次后重测。 |
| 健康度 | 相邻两次快照跌幅 > 5 个百分点 | 突然掉档，优先怀疑校准而非真实衰减，建议隔一周复测确认。 |

`total_operating_time_h`（累计运行小时）和 `TimeAtHighSoc`（高电量停留时长）不构成异常，
但可以用来解释衰减偏快的原因，属于「小建议」章节的素材，不要放进异常清单吓人。

## 六、综合结论四档

按下面的顺序判，命中即停：

1. **需要送修检测** —— 命中任一硬故障信号（`permanent_failure_status` 非 0、
   `condition` 明确异常、`cell_disconnect_count` 持续增长）。
   结论落在「硬件异常」而不是「电池老化」上，这两件事的处理路径完全不同。

2. **建议更换电池** —— 健康度 < 80%，或循环次数已达设计寿命的 100%。

3. **可以开始关注** —— 健康度 80% ~ 85%，或衰减倍率 > 2，或循环次数达设计寿命 80%。
   说清楚「现在还能正常用，但建议在 X 个月内做好更换计划」，给客户留决策空间。

4. **状态健康** —— 以上都不命中。明确说不需要做任何处理，然后给两三条保养建议就收尾。
   **这一档不要推荐更换类服务**，理由见 `lenovo-offers.md`。

## 七、使用建议素材库

按检测结果挑 2~4 条给出，**不要一次性全倒给客户**——建议给多了等于没给。
挑选依据写在每条后面的括号里。

**充电习惯**
- 日常尽量让电量在 20%~80% 区间波动，避免长期满电或长期深度放电。
  （通用，任何档位都适用）
- 长期插电办公的话，打开系统自带的电池健康管理 / 充电阈值设置：
  macOS「系统设置 → 电池 → 电池健康 → 优化电池充电」，
  Windows 上是厂商工具里的「养护模式 / 保养模式」（联想电脑管家、Lenovo Vantage 里可开）。
  （`external_connected=true` 且高电量停留时间长时优先给这条）

**温度管理**
- 避免在床上、沙发、被褥上长时间使用，堵住进风口会让电池长期处在高温下。
  （`lifetime_max_temp_c` ≥ 50 时必给）
- 定期清理散热口积灰；夏季高温环境下减少边充边玩大型游戏。
  （高温 + 游戏本机型时给）

**长期存放**
- 超过一个月不用，把电量充到 50% 左右再关机存放，别满电或空电长期搁置。
  （`total_operating_time_h` 相对购机时长明显偏低，说明经常闲置时给）

**校准**
- 如果系统显示的续航时间跳变很大，可以做一次完整校准：充满 → 正常使用放电到自动关机 →
  静置几小时 → 一次性充满。校准修正的是电量计读数，不会让电池"变健康"，
  这点要跟客户讲清楚，否则会有预期落差。
  （两种口径分歧 ≥ 3 个百分点，或健康度突然掉档时给）

**电源配件**
- 用原装或符合规格的适配器充电，功率不足的充电器会让机器边充边掉电、延长高温时间。
  （`adapter_watts` 明显低于机型标称功率时给）
